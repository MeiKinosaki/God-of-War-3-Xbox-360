# Bootstrap build and test procedure

## What exists

- `src/main.c`: a minimal, original C entry point that returns success.
- `Makefile`: a host check and a separate Xenon cross-build target.
- `tests/check_source.py`: static repository checks.
- These files are scaffolding only; they do not implement God of War III.

## Host-side checks

Run from the repository root:

```sh
python3 tests/check_source.py
make host-check
```

These checks validate the scaffold on a host computer only. They do not produce a Xenon ELF, prove libXenon compatibility, or test an Xbox 360.

## Xenon target build

First install and verify a compatible Free60/libXenon toolchain using its official documentation. Record the compiler version and target. Then run:

```sh
make xenon-elf
```

The Makefile default assumes the compiler command is named `xenon-gcc`; override `XENON_CC` if the selected toolchain uses a different executable. The exact flags, startup objects, libraries, and output format must be confirmed for that toolchain. Do not report a successful build until the command has actually completed and the output has been inspected.

## ELF validation checklist

1. Preserve the complete compiler log.
2. Inspect the output with the toolchain's supported object inspection utility.
3. Confirm ELF class, endianness, machine architecture, and executable type.
4. Check unresolved symbols and required runtime/startup objects.
5. Test startup on compatible hardware or an appropriate development environment.
6. Record device/environment, exact command, result, and known limitations.

## XEX is a later milestone

Do not rename an ELF to `default.xex`. Confirm a supported Xbox 360 executable packaging/linking workflow, then validate the resulting XEX with suitable tools and test it on target hardware. No XEX is generated by this bootstrap Makefile.
